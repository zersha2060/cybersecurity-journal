<h2>2. Overview</h2>

This lab demonstrates a Broken Access Control vulnerability in which access restrictions can be bypassed by directly accessing restricted URLs.

The application attempts to enforce access control by checking the URL of incoming requests. However, these restrictions can be circumvented when the application relies on URL-based access controls without properly enforcing authorization on the server side.

This creates a security weakness because an unauthorized user may be able to access administrative functionality by manipulating the request URL or accessing restricted endpoints directly.

<h2>3. Objective</h2>

The objective of this lab is to identify and exploit an access control weakness that allows a regular user to access administrative functionality through direct URL access.

The exercise demonstrates why applications should enforce authorization checks on every sensitive request rather than relying solely on URL-based restrictions.

<h2>4. Vulnerability Explanation</h2>

Broken Access Control occurs when an application does not properly enforce restrictions on what authenticated users are allowed to access or perform.

In this scenario, the application relies on URL-based access restrictions to protect administrative functionality.

If these restrictions are not consistently enforced, an attacker may be able to bypass them by directly requesting an administrative endpoint.

This vulnerability can allow unauthorized users to access restricted functionality even when the application interface does not provide links to those resources.

<h2>5. Technical Methodology</h2>

<h3>5.1 Initial Reconnaissance</h3>

I accessed the PortSwigger lab application and explored its available functionality.

The initial objective was to understand how the application handled user authentication and restricted administrative resources.

I also examined the application's navigation and identified areas where access restrictions might be implemented.

<h3>5.2 Vulnerability Investigation</h3>

I used Burp Suite to inspect the HTTP requests generated by the application.

During the investigation, I examined how the application handled requests to restricted URLs and whether access control was consistently enforced.

I identified that the application relied on URL-based restrictions to control access to administrative functionality.

This suggested that the access control mechanism might be vulnerable to direct URL access.

<h3>5.3 Exploitation</h3>

After identifying the potential weakness, I investigated whether the administrative functionality could be accessed without using the application's normal navigation.

I tested direct access to the restricted administrative endpoint and examined how the application responded to the request.

The application failed to properly enforce the intended access restrictions, allowing unauthorized access to administrative functionality.

<h3>5.4 Verification</h3>

After accessing the restricted functionality, I verified whether the application allowed the administrative operation to be performed.

The successful completion of the lab demonstrated that URL-based access restrictions could be circumvented due to insufficient server-side authorization enforcement.

<h2>6. Findings</h2>

**Identified Vulnerability:** Broken Access Control – URL-Based Access Control Bypass

**Root Cause:** The application relied on URL-based restrictions without consistently enforcing authorization checks on the server side.

**Security Impact:** An unauthorized user could potentially access administrative endpoints and perform restricted operations.

**Result:** Lab successfully completed.

<h2>7. Security Impact</h2>

Potential consequences include:

- Unauthorized access to administrative functionality.
- Bypass of application access restrictions.
- Unauthorized modification of application data.
- Exposure of sensitive information.
- Unauthorized execution of privileged operations.
- Potential privilege escalation depending on the functionality exposed.

<h2>8. Recommended Remediation</h2>

To prevent this vulnerability, developers should:

1. Enforce authorization checks on the server side for every sensitive endpoint.
2. Never rely solely on URL-based restrictions to protect administrative functionality.
3. Verify the authenticated user's permissions before processing sensitive requests.
4. Apply the principle of least privilege.
5. Ensure that direct requests to restricted resources are properly validated.
6. Implement centralized access control mechanisms.
7. Log and monitor unauthorized access attempts.
